# Explicit degree17 stage plans and independent marker coverage

23 October 2026. Ordinary proof development. These tools bind already completed exact certificates; they run no producer, model build, solver or new replay. A successful complete plan excludes its one recorded root-link kind under the stated structural and terminal imports. It is not a claim about all degree17 kinds or the global problem.

## Explicit inputs and antecedents

`check_d17_stage_plan.py` accepts a JSON plan with schema `d17-stage-proof-plan-v1`, one `kind`, and an ordered `nodes` list. For P10 kinds it additionally requires the explicit path `p10_internal_summary` to the frozen twelve-case component exclusion package. P9 kinds must not supply that premise.

Each node has `id`, `receipt`, `replay`, and `uses` fields. Optional `receipt_sha256` and `replay_sha256` pin the named files. `uses` lists only distinct earlier node IDs. Paths are absolute or relative to the plan file. Optional `construction_inputs` is a list of path/hash records used when preparing the explicit list; they are bound as provenance and supply no mathematical conclusions. Optional `unproved_candidates` records diagnostic entries with `case`, `receipt` and `receipt_sha256`; these are hash-bound but confer no facts. Unknown plan or node fields fail closed.

The validator never searches for a latest receipt or chooses between alternative runs. A phase-one node names its active phase-one receipt, which must bind an original status2 receipt and preserve its model metadata. Every listed leaf needs an existing matching exact replay with PASS, unchanged bound inputs, the supported frozen source and replayer, a consistent premise fingerprint, and a strictly negative zero-objective gap or trace upper bound strictly below51. It checks required independent triangle, H27 and v4 B4/pruning evidence. Missing, unfinished, failed and nonstrict listed leaves are rejected even in partial mode.

Initially a P10 plan knows every Y-internal four-set is absent, after separately binding the twelve original component receipts, exact replay files, their negative integer gaps, the frozen coverage summary and dependencies. A P9 plan starts with no such fact. Its four completed IY leaves may be explicitly reused as initial nodes.

The facts available at a node are the P10 initial fact, when applicable, and the union of the transitive facts attached to its listed predecessors. The node's `forbidden` exact traces must be justified by those facts. A forbidden core four-set requires that actual four-set already absent. A forbidden trace whose core restriction is a mixed triple requires the previous exclusion of every exterior completion of that triple. No inference from an absent four-set to its proper subsets is permitted. `empty_z` requires every Z four-set absent; `forbid_four_core` requires every core four-set absent. An empty assigned-Z pattern is allowed only once Z emptiness is proved. Nonempty assigned patterns and extra-actual-member branches need separate partition adapters and are rejected by this ordinary plan validator.

A strict internal or four-core marker leaf excludes its entire reconstructed marker orbit. A strict E3 leaf excludes all actual members whose core trace lies in the corresponding mixed-triple orbit: its one actual exterior point can be relabelled to the canonical marker without restricting other exterior points. A strict unmarked leaf directly excludes the kind. Each predecessor fact is a full component-automorphism orbit. Therefore these facts are invariant when relabelling a target marker to its canonical representative. A receiving receipt may forbid only part of an already absent orbit; the larger invariant fact still justifies every such restriction after relabelling. This permits genuine stage0/stage1 and longer staged exclusion chains without circularity.

The default requires complete marker-stage coverage or a direct unmarked exclusion. `--allow-partial` can instead save only the verified listed facts and explicit missing core-four/mixed-three masks. Its status does not claim closure.

## Literal geometry and arbitrary support

The checker reconstructs the ten-block P10 system from its literal triples, P9 by deleting012, Q8 from its two triangle hubs and two leaf triples, and all eight H_i from their frozen literal certificate rows. It checks each H_i is an intersecting sunflower-free triple family with its stated six- or seven-point support. The two P8 deletion forms are independently reconstructed as the two orbits of deleted P10 block pairs under all60 automorphisms of P10.

For each component the checker examines every permutation of its six- or seven-point literal support to obtain its full automorphism group. It then constructs every IY, IZ, mixed-four-core and mixed-three-core-plus-one-exterior marker orbit under the component-product group. Every actual four-subset or mixed triple in the finite domain is accounted for once. The complete reconstructed catalogue, representative masks, orbit elements, component root triples and group orders must match each supplied producer receipt. No producer import, producer orbit count or guessed subgroup supplies coverage.

These finite label sets describe the supports of the already classified components. They are not an ambient-support cutoff for F. The universal high-link split, I8/I9/I10 classification, arbitrary-support reduction for I7 and finite I7 classification remain the explicit imports detailed in `D17-I7-classification-route.md`, `D17-full-model-bridge.md`, the independently checked `D17-i7-coverage.json` and their source registries. The current checker verifies the literal certificate/templates, not a new exhaustive classification of all triple families.

## Terminal argument after complete stages

Suppose every core four-set and every mixed core triple has been excluded. Every residual member then has core trace of size at most2, or a pure triple on Y or Z. The finite checker verifies that every subset of Y of size at most2 is avoided by a Y block, and that every subset of Z of size at most1 is avoided by a Z block.

If two residual members A,B were disjoint, their union must meet every block in each component: otherwise the corresponding root cone would be disjoint from both, giving an empty-core sunflower. Hence their union has at least3 Y points and at least2 Z points. If neither residual trace is a pure Y triple, one member must supply two Y points and the other at least one; the former has no Z point and the latter at most one, a contradiction. If one is a pure Y triple, the other must supply at least2 Z points and thus no Y point. The pure Y triple must therefore itself meet every Y block.

Remove the actual family T_Y of residual members whose trace is a transversal triple on Y. The remaining residual family is intersecting, so H27 gives r≤27+|T_Y|. The global triple-codegree bound2 gives at most two completions for each such triple, reduced to one residual completion whenever its root cone is present.

For P10 the transversal triples are exactly its ten blocks, giving |T_Y|≤10 and r≤37. For P9 they are its nine retained blocks, the omitted P10 block012 and its complement345. The first nine have one residual completion each, and the two additional triples at most two each. Thus |T_Y|≤13 and r≤40. The checker verifies these finite transversal sets and capacities directly. Both bounds contradict the necessary r≥68−17=51. This is an ordinary terminal proof on arbitrary exterior support, conditional on H27 and the stated codegree bound.

## Preparing plans from the eight-kind exterior driver

`prepare_d17_stage_plan.py` consumes named completed `--e4-progress` and optional `--e3-progress` files from `run_d17_exterior_stage.py`, for H1,…,H6 and P9-P8-i1/i2. It imports no producer and uses no glob. It copies the exact listed internal and strict exterior receipt paths/hashes into a new plan; completed but nonstrict/failed exterior cases are retained only in `unproved_candidates`, never as exclusions. For P9 it copies the four relevant explicit IY receipt/replay pairs from the named completed Y manifest. Stage0 internal nodes use IY; stage1 nodes additionally use all listed strict stage0 nodes; E4 nodes use all IY/internal nodes; E3 nodes use the listed proved-candidate E4 nodes. The E3 list must hash-bind the supplied E4 list and identical antecedent lists; if those E4 nodes do not actually cover all core four-sets, the validator rejects an E3 node's `forbid_four_core` premise even in partial mode.

The preparation tool records a deterministic explicit replay path for each receipt and its hash when already present. It does not require the replay to have finished, does not trust discovery diagnostics as proof, and reports only `PREPARED_EXPLICIT_PLAN_NOT_VALIDATED`. The separate validator checks all named replays and independently reconstructs complete coverage before reporting a conclusion. Discovery-list completeness counters are used only to refuse unfinished plan construction; the validator's literal domains determine actual completeness. Additional later-stage E4 nodes can be appended to a new explicit plan, naming the earlier strict E4 node IDs in `uses` to justify precisely the new forbidden masks. No first-pass-completeness assumption is built into the generic validator.

The initial supported producer adapters are frozen original/v2/v3/v4. H7's equality-plus-two-v5-leaf split is a separate rule: its v5 leaves have extra actuality premises, so neither alone excludes the original IZ13 orbit. Such a split requires the independent equality extraction, all preceding orbit exclusions, and both extra-member exact certificates. This ordinary validator deliberately rejects v5 until that separate rule is supplied.
